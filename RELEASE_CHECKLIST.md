# Release Checklist

Финальный чек-лист перед переводом pull request из draft в ready for review и последующим merge в `main`.

## 1. Автоматические проверки

Выполнить локально или дождаться успешного GitHub Actions:

```bash
npm run check
npm run build:zip
```

Ожидаемый результат:

- все unit-тесты проходят;
- синтаксическая проверка всех JS-модулей проходит;
- ZIP-архив создаётся в `dist/`;
- в архив не попадают служебные файлы разработки: `.git`, `.github`, `test`, `node_modules`, `dist`.

## 2. Установка расширения из папки

1. Открыть `chrome://extensions/` или `edge://extensions/`.
2. Включить режим разработчика.
3. Нажать **Загрузить распакованное расширение**.
4. Выбрать папку проекта.
5. Убедиться, что расширение загрузилось без ошибок manifest.

## 3. Проверка базовой отправки текста

Проверить минимум один сценарий:

1. Выделить текст на любой странице.
2. Открыть контекстное меню.
3. Выбрать **Send to AI** → один из включённых сервисов.
4. Убедиться, что сервис открылся или активировалась уже открытая вкладка.
5. Убедиться, что текст вставлен в поле ввода.
6. Проверить badge на иконке: `OK` при успехе, `ERR` при ошибке.

## 4. Проверка вставки в ChatGPT (paste-first)

ChatGPT использует paste-first вставку в contenteditable-поле. Обязательно проверить:

1. Отправить текст в **уже открытую вкладку ChatGPT** 3–5 раз.
2. Убедиться, что каждый раз появляется ровно одна копия текста — без дублирования.
3. Повторить отправку в **новую вкладку ChatGPT**.
4. Проверить, что диагностика успешной вставки показывает:
   - `status = success`;
   - `method = paste-event`;
   - `actualLength ≈ expectedLength`.
5. Проверить, что повторная вставка не очищает и не затирает уже вставленный текст.

## 5. Проверка специальных команд

Проверить:

- перевод в Qwen;
- перевод в ChatGPT;
- саммари в ChatGPT;
- фактчекинг в ChatGPT.

Ожидаемый результат: в сервис вставляется не просто выделенный текст, а полный prompt с выбранной инструкцией.

## 6. Smoke-тест Grok и Qwen (usePasteFirst)

Grok и Qwen используют paste-first вставку в SPA:

- **Grok**: отправить выделенный текст в уже открытую вкладку и в новую вкладку; убедиться, что текст вставлен ровно один раз и не затёрт фреймворком (React).
- **Qwen**: отправить текст в Qwen и проверить команду перевода.

## 7. Проверка страниц и ссылок

Проверить для текущей страницы:

- саммари;
- фактчекинг;
- перевод;
- тезисы.

Проверить для ссылки:

- саммари;
- фактчекинг;
- перевод;
- тезисы.

Ожидаемый результат: prompt содержит URL и корректную инструкцию.

## 8. Проверка пользовательских команд

1. Открыть настройки расширения.
2. Создать пользовательскую команду.
3. Указать сервис, контекст и prompt-шаблон.
4. Проверить предпросмотр.
5. Сохранить настройки.
6. Открыть контекстное меню и выполнить команду.

Отдельно проверить переменные:

- `{selection}`;
- `{url}`;
- `{title}`;
- `{date}`;
- `{service}`;
- `{pageText}`;
- `{youtubeUrl}`.

## 9. Проверка извлечения текста страницы

1. Создать команду с контекстом **Текст страницы**.
2. Использовать в шаблоне `{pageText}`.
3. Открыть обычную статью или страницу с текстом.
4. Выполнить команду.

Ожидаемый результат: в prompt подставляется видимый текст страницы, максимум 30 000 символов.

## 10. Проверка профилей команд

1. Создать несколько пользовательских команд с разными профилями.
2. Выбрать активный профиль в настройках.
3. Сохранить.
4. Проверить контекстное меню.

Ожидаемый результат:

- команды выбранного профиля видны;
- команды других профилей скрыты;
- команды без профиля остаются видимыми.

## 11. Проверка YouTube-шаблонов

Проверить YouTube-ссылку для сценариев:

- статья по YouTube-транскрипции;
- краткое резюме;
- список фактов;
- Telegram-пост;
- тезисы для исследования.

Также проверить в настройках:

- включение и отключение шаблона;
- изменение названия;
- изменение сервиса;
- редактирование prompt;
- предпросмотр;
- переменную `{youtubeUrl}`.

## 12. Проверка импорта и экспорта

1. Настроить сервисы, профили, пользовательские команды и YouTube-шаблоны.
2. Экспортировать настройки в JSON.
3. Сбросить настройки.
4. Импортировать JSON.
5. Убедиться, что настройки восстановились.

## 13. Проверка диагностики

1. Смоделировать ошибку вставки или выбрать сервис, где поле ввода не найдено.
2. Открыть настройки.
3. Перейти во вкладку **Диагностика**.
4. Проверить запись ошибки.
5. Раскрыть детали.
6. Очистить журнал.

Важно: журнал не должен сохранять полный prompt.

## 14. Проверка интерфейса настроек

Проверить:

- вкладки **Основное**, **Команды**, **Диагностика**, **Данные**;
- поиск по настройкам;
- поиск по всем вкладкам;
- кнопки **Включить видимое** и **Выключить видимое**;
- сохранение последней активной вкладки.

## 15. Финальные действия

Перед merge:

1. Убедиться, что PR `mergeable: true`.
2. Убедиться, что GitHub Actions зелёный.
3. Убедиться, что `README.md`, `CHANGELOG.md`, `RELEASE.md` и этот чек-лист актуальны.
4. Снять draft-статус с PR.
5. Выполнить merge в `main` только после успешной проверки.
