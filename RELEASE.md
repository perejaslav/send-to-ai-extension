# Руководство по релизу

Этот документ описывает, как подготовить и проверить релиз расширения **Send to AI**.

## 1. Перед началом

Работай не в `main`, а в отдельной ветке.

Убедись, что установлен Node.js. Для проверки выполни:

```bash
node --version
npm --version
```

## 2. Проверка проекта

Запусти полную проверку:

```bash
npm run check
```

Она должна завершиться без ошибок.

## 3. Проверка версии

Версия должна быть синхронизирована в двух местах:

- `manifest.json` → поле `version`;
- `package.json` → поле `version`.

Например:

```json
"version": "X.Y"
```

в `manifest.json` и:

```json
"version": "X.Y.Z"
```

в `package.json`.

## 4. Обновление changelog

Перед релизом обнови `CHANGELOG.md`:

1. Перенеси изменения из `Unreleased` в новый блок версии.
2. Укажи номер версии.
3. Кратко опиши, что добавлено, изменено и исправлено.

## 5. Сборка ZIP-архива

Выполни:

```bash
npm run build:zip
```

Скрипт создаст папку `dist/` и положит туда ZIP-архив расширения.

Формат имени:

```text
send-to-ai-extension-vX.Y.Z.zip
```

## 6. Что входит в ZIP

В архив должны попадать рабочие файлы расширения:

- `manifest.json`;
- JavaScript-файлы;
- HTML-файлы;
- CSS-файлы;
- иконки;
- README-файлы;
- лицензия, если она есть.

В архив не должны попадать:

- `.git/`;
- `.github/`;
- `node_modules/`;
- `dist/`;
- `test/`;
- служебные документы разработки (`TECHNICAL_SPEC.md` и аналогичные);
- временные файлы.

## 7. Ручная проверка ZIP

1. Распакуй ZIP в отдельную временную папку.
2. Открой `chrome://extensions/` или `edge://extensions/`.
3. Включи режим разработчика.
4. Нажми **Загрузить распакованное расширение**.
5. Выбери распакованную папку.
6. Проверь:
   - расширение устанавливается без ошибок;
   - появляется контекстное меню;
   - выделенный текст отправляется в ChatGPT;
   - выделенный текст отправляется в Qwen;
   - popup открывается;
   - страница настроек открывается;
   - настройки сохраняются.

## 8. Ручная проверка вставки в ChatGPT

ChatGPT использует paste-first вставку в contenteditable-поле. Обязательно проверь:

1. **Уже открытая вкладка ChatGPT** — отправь текст 3–5 раз подряд в одну и ту же открытую вкладку.
2. Убедись, что каждый раз появляется ровно одна копия текста (без дублирования).
3. Открой **новую вкладку ChatGPT** и повтори отправку.
4. Проверь команды **«Перевести на русский»**, **«Сделать саммари»** и **«Провести фактчекинг»**.
5. Проверь отправку на страницу/ссылку через блок **«Страницы и ссылки»**.

Ожидаемая диагностика успешной paste-first вставки:

```text
status = success
method = paste-event
actualLength ≈ expectedLength
```

## 9. Smoke-тест Grok и Qwen

Grok и Qwen используют `usePasteFirst` и SPA-загрузку:

- **Grok**: отправь выделенный текст в уже открытую вкладку и в новую вкладку; проверь, что текст вставлен ровно один раз и не затёрт фреймворком.
- **Qwen**: отправь текст в Qwen и проверь команду перевода.

## 10. Проверка прав доступа

Перед публикацией проверь `manifest.json`.

Нельзя добавлять широкие права без необходимости. Предпочтительно использовать точные домены ИИ-сервисов в `host_permissions`.

## 11. GitHub Release

После проверки:

1. Создай tag версии.
2. Создай GitHub Release.
3. Прикрепи ZIP-архив из `dist/`.
4. В описание релиза добавь выдержку из `CHANGELOG.md`.

Пример:

```bash
git tag vX.Y.Z
git push origin vX.Y.Z
```

## 12. Минимальный чеклист релиза

- [ ] `npm run check` проходит.
- [ ] Версия обновлена в `manifest.json`.
- [ ] Версия обновлена в `package.json`.
- [ ] `CHANGELOG.md` обновлён.
- [ ] `npm run build:zip` создаёт архив.
- [ ] ZIP проверен вручную в браузере.
- [ ] Вставка в ChatGPT проверена в уже открытой вкладке (без дублирования).
- [ ] Smoke-тест Grok и Qwen пройден.
- [ ] Права доступа в `manifest.json` проверены.
- [ ] GitHub Release создан.

Подробный чек-лист перед merge — в `RELEASE_CHECKLIST.md`.
