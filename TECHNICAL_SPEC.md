# Техническое описание и дорожная карта: Send to AI

## 1. Назначение документа

Документ описывает текущее состояние расширения **Send to AI** и оставшиеся задачи развития.

Цель проекта — превратить расширение из набора заранее прописанных команд отправки текста в ИИ-сервисы в гибкий браузерный центр ИИ-команд: выделил текст, ссылку или страницу, выбрал нужное действие, получил готовый запрос в выбранном ИИ-сервисе.

Все изменения должны внедряться постепенно. Каждый этап обязан оставлять проект в рабочем состоянии.

## 2. Текущее состояние (v4.5)

Расширение поддерживает 12 сервисов: **ChatGPT, Qwen AI, Grok, Google Gemini, Google AI Studio, Claude, DeepSeek, Z.ai, Kimi AI, Ernie, Minimax, StepFun**.

Реализовано:

- отправка выделенного текста в любой из поддерживаемых сервисов из контекстного меню;
- переиспользование уже открытой вкладки сервиса (фокус + вставка) либо открытие новой вкладки;
- автоматическая вставка текста с запасными стратегиями: paste-first для React/contenteditable-сервисов с ожиданием асинхронного commit до 800 мс, fallback к `execCommand`/`textContent`, повторная проверка через `settleMs` и защита от дублирования в уже открытой вкладке;
- статус вставки через badge на иконке расширения (`OK` / `ERR`);
- закреплённые сервисы **ChatGPT**, **Qwen AI** и **Grok** с вложенными командами: отправка, перевод на русский, саммари, фактчекинг;
- подменю **«Страницы и ссылки»**, **«Страницы и ссылки в Qwen»** и **«Страницы и ссылки в Grok»** с командами саммари, фактчекинга, перевода и тезисов для текущей страницы и ссылок;
- popup для быстрой отправки выделенного текста и запуска команд;
- пользовательские команды с prompt-шаблонами и переменными `{selection}`, `{url}`, `{title}`, `{date}`, `{service}`, `{pageText}`, `{youtubeUrl}`;
- извлечение видимого текста текущей страницы для переменной `{pageText}`;
- профили команд: базовый, маркетинг, редактура, перевод, исследование, YouTube, Hermes Agent;
- импорт и экспорт настроек в JSON с нормализацией;
- журнал диагностики последних ошибок без сохранения текста prompt;
- пять редактируемых YouTube-шаблонов: статья, краткое резюме, список фактов, Telegram-пост, тезисы для исследования — с выбором сервиса и переменной `{youtubeUrl}`;
- интерфейс настроек с вкладками, поиском, массовым переключением видимости и светлой/тёмной темой;
- релизный ZIP-архив одной командой (`npm run build:zip`);
- автоматическая проверка проекта через GitHub Actions и локально (`npm run check`).

## 3. Общие правила реализации

- Не вносить изменения напрямую в `main`.
- Для каждой крупной доработки создавать отдельную ветку.
- Не ломать существующие сценарии.
- После каждого этапа запускать `npm run check`.
- Новую бизнес-логику покрывать тестами.
- Не расширять права расширения без необходимости.
- Старые настройки должны безопасно нормализоваться после обновления.
- Интерфейс должен быть понятным пользователю без технической подготовки.

## 4. Реализованные этапы

Перечисленные ниже этапы дорожной карты выполнены и отражены в `CHANGELOG.md`:

- **Этап 1. Подготовка проекта к развитию** — `CHANGELOG.md`, `CONTRIBUTING.md`, `RELEASE.md`, сборка ZIP, GitHub Actions.
- **Этап 2. Система пользовательских команд** — `custom-commands.js`, нормализация, подстановка переменных, подключение к меню, тесты.
- **Этап 3. Интерфейс управления пользовательскими командами** — создание, редактирование, удаление, отключение команд и предпросмотр prompt в настройках.
- **Этап 4. Извлечение видимого текста страницы** — `page-extractor.js`, переменная `{pageText}`, контекст `page_text`.
- **Этап 5. Импорт и экспорт настроек** — экспорт в JSON, импорт с нормализацией, сброс к настройкам по умолчанию.
- **Этап 6. Профили команд** — `profiles.js`, выбор активных профилей, фильтрация команд в меню.
- **Этап 7. Улучшение диагностики вставки** — статусы ошибок, журнал в `chrome.storage.local`, панель диагностики в настройках, подробная диагностика вставки из `insertion.js`.
- **Этап 9. Улучшение YouTube-сценариев** — редактируемые шаблоны с пятью сценариями и переменной `{youtubeUrl}`.
- **Этап 10. Улучшение интерфейса настроек** — вкладки, поиск, массовое переключение, предпросмотр, тема.

## 5. Дорожная карта (нереализованные задачи)

### 5.1. Локальные сервисы и ИИ-агенты

Цель — отправлять текст не только в публичные веб-сервисы, но и в локальные инструменты.

Возможные цели:

- Hermes Agent Web UI;
- Open WebUI;
- локальный API;
- LM Studio через совместимый интерфейс;
- Ollama через промежуточный локальный сервер;
- собственный обработчик на `127.0.0.1`.

Режимы:

- **Режим web** — открыть локальный веб-интерфейс и вставить prompt через текущий механизм вкладок и вставки.
- **Режим api** — отправить prompt HTTP-запросом на локальный адрес.

Задачи:

1. Добавить тип сервиса `web` или `api`.
2. Для `web` использовать текущий механизм открытия вкладки и вставки.
3. Для `api` добавить отправку `POST`-запроса.
4. Добавить настройки локального сервиса: название, URL, метод, шаблон тела запроса, заголовки при необходимости.
5. Добавить предупреждения о безопасности: явное включение локальных API-сервисов, защита от случайной отправки чувствительного текста.

Файлы: `services.js`, `settings.js`, `options.html`, `options.js`, `background.js`, `README.md`.

### 5.2. Подготовка к публичному релизу

Цель — подготовить проект к распространению через магазины расширений.

Задачи:

1. Добавить скриншоты в README.
2. Добавить раздел безопасности с объяснением прав доступа.
3. Добавить релизный ZIP в GitHub Releases.
4. Проверить готовность к Chrome Web Store и Edge Add-ons.

Файлы: `README.md`, `README.en.md`, `RELEASE.md`, при необходимости `.github/workflows/release.yml`.

## 6. Критерии готовности проекта

Проект считается завершённым по дорожной карте, когда:

- пользователь может создать собственную команду через интерфейс;
- команда появляется в контекстном меню и работает с выбранным сервисом;
- настройки можно перенести на другой компьютер;
- есть профили под разные задачи;
- ошибки вставки понятны;
- есть ZIP-релиз;
- проверки запускаются автоматически;
- документация объясняет установку, настройку, безопасность и развитие проекта.
