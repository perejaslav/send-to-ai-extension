# Техническое задание: развитие Send to AI

## 1. Назначение документа

Этот документ описывает поэтапный план доработки расширения **Send to AI**.

Цель — превратить расширение из набора заранее прописанных команд отправки текста в ИИ-сервисы в гибкий браузерный центр ИИ-команд: выделил текст, ссылку или страницу, выбрал нужное действие, получил готовый запрос в выбранном ИИ-сервисе.

Все изменения должны внедряться постепенно. Каждый этап обязан оставлять проект в рабочем состоянии.

## 2. Текущее состояние

Расширение уже умеет:

- отправлять выделенный текст в ChatGPT, Qwen, Gemini, Claude, DeepSeek, Grok, Kimi, Z.ai, Google AI Studio и другие сервисы;
- переиспользовать уже открытую вкладку сервиса;
- автоматически вставлять текст в поле ввода;
- показывать статус вставки через значок расширения;
- создавать контекстное меню браузера;
- выполнять специальные команды: перевод, саммари, фактчекинг;
- работать со ссылками и текущими страницами через готовые prompt-шаблоны;
- отправлять YouTube-ссылки в Gemini с готовыми сценариями;
- настраивать порядок сервисов и видимость части команд;
- запускать проверки через `npm run check`.

## 3. Главная проблема

Сейчас специальные команды в основном зашиты в коде. Чтобы добавить новый сценарий, нужно менять JavaScript-файлы.

Это мешает развитию. Пользователь должен иметь возможность сам добавлять команды через интерфейс: например, «сделай SEO-анализ», «преврати текст в Telegram-пост», «создай ТЗ для Hermes Agent», «сделай фактчекинг исторического текста», «переведи и литературно обработай».

## 4. Целевое состояние

После реализации дорожной карты расширение должно уметь:

1. Хранить пользовательские команды в настройках.
2. Создавать, редактировать, удалять, включать и отключать команды через интерфейс.
3. Использовать переменные в prompt-шаблонах: `{selection}`, `{url}`, `{title}`, `{date}`, `{service}`, `{pageText}`, `{youtubeUrl}`.
4. Применять команды к выделенному тексту, ссылке, текущей странице, YouTube-ссылке и извлечённому тексту страницы.
5. Извлекать видимый текст текущей страницы и отправлять его в ИИ.
6. Импортировать и экспортировать настройки в JSON.
7. Поддерживать профили команд: базовый, маркетинг, перевод, редактура, исследование, YouTube, Hermes Agent.
8. Улучшить диагностику ошибок вставки.
9. Поддерживать локальные сервисы и ИИ-агенты.
10. Собирать релизный ZIP-архив одной командой.
11. Проверять проект через GitHub Actions.

## 5. Общие правила реализации

- Не вносить изменения напрямую в `main`.
- Для каждой крупной доработки создавать отдельную ветку.
- Не ломать существующие сценарии.
- После каждого этапа запускать `npm run check`.
- Новую бизнес-логику покрывать тестами.
- Не расширять права расширения без необходимости.
- Старые настройки должны безопасно нормализоваться после обновления.
- Интерфейс должен быть понятным пользователю без технической подготовки.

## 7. Этап 2. Система пользовательских команд

### Цель

Сделать команды настраиваемыми без изменения кода.

### Модель команды

```json
{
  "id": "custom-summary-page",
  "title": "Подробное саммари страницы",
  "description": "Анализирует текущую страницу и выделяет ключевые факты",
  "enabled": true,
  "serviceId": "sendToChatGPT",
  "contextType": "page",
  "template": "Проанализируй страницу по URL:\n{url}\n\nЗаголовок: {title}\n\nСделай подробное саммари.",
  "menuGroup": "custom",
  "order": 100
}
```

### Типы контекста

- `selection` — выделенный текст;
- `page` — текущая страница;
- `link` — ссылка;
- `youtube` — YouTube-ссылка;
- `page_text` — извлечённый текст текущей страницы.

### Переменные

- `{selection}` — выделенный текст;
- `{url}` — URL страницы или ссылки;
- `{title}` — заголовок страницы;
- `{date}` — текущая дата;
- `{service}` — название сервиса;
- `{pageText}` — извлечённый текст страницы;
- `{youtubeUrl}` — нормализованная YouTube-ссылка.

### Задачи

1. Создать `custom-commands.js`.
2. Реализовать нормализацию команд.
3. Реализовать подстановку переменных в шаблон.
4. Реализовать безопасную генерацию `id`.
5. Добавить настройки `customCommands`.
6. Подключить пользовательские команды к `menus.js`.
7. Подключить выполнение команд в `background.js`.
8. Добавить тесты:
   - нормализация команды;
   - подстановка переменных;
   - отключённые команды не попадают в меню;
   - команда с неизвестным сервисом не ломает расширение.

### Файлы

- `custom-commands.js`
- `settings.js`
- `menus.js`
- `background.js`
- `test/custom-commands.test.js`
- `test/menus.test.js`
- `README.md`

### Критерии готовности

- Пользовательские команды хранятся в `chrome.storage.sync`.
- Команды появляются в меню.
- Переменные корректно подставляются.
- Старые встроенные команды работают.
- Тесты проходят.

## 9. Этап 4. Извлечение видимого текста страницы

### Цель

Дать расширению возможность отправлять в ИИ не только URL, но и сам видимый текст страницы.

Это нужно для страниц, которые ИИ-сервис не может открыть сам: закрытые сайты, страницы за авторизацией, локальные страницы, сайты с защитой.

### Что извлекать

- URL;
- заголовок;
- meta description при наличии;
- основной видимый текст;
- выделенный текст при наличии.

### Задачи

1. Создать `page-extractor.js`.
2. Реализовать извлечение видимого текста.
3. Исключать `script`, `style`, скрытые элементы и явный мусор.
4. Ограничить максимальный размер текста.
5. Добавить переменную `{pageText}`.
6. Добавить тип контекста `page_text`.
7. Добавить предустановленную команду «Отправить текст страницы в ChatGPT».

### Риски

- Страница может содержать слишком много мусора.
- На некоторых сайтах расширение не сможет получить доступ к содержимому.
- Очень длинный текст может не поместиться в поле ввода.

### Снижение рисков

- Добавить лимит символов.
- Показывать предупреждение об обрезке.
- Не заменять обычный режим отправки URL, а добавить отдельный режим.

### Файлы

- `page-extractor.js`
- `background.js`
- `custom-commands.js`
- `settings.js`
- `menus.js`
- `test/page-extractor.test.js`
- `README.md`

### Критерии готовности

- Текст страницы можно извлечь.
- `{pageText}` можно использовать в шаблоне.
- При недоступности страницы показывается понятная ошибка.
- Старые команды работают.

## 13. Этап 8. Локальные сервисы и ИИ-агенты

### Цель

Добавить возможность отправлять текст не только в публичные веб-сервисы, но и в локальные инструменты.

### Возможные цели

- Hermes Agent Web UI;
- Open WebUI;
- локальный API;
- LM Studio через совместимый интерфейс;
- Ollama через промежуточный локальный сервер;
- собственный обработчик на `127.0.0.1`.

### Режимы

**Режим web** — открыть локальный веб-интерфейс и вставить prompt.

**Режим api** — отправить prompt HTTP-запросом на локальный адрес.

### Задачи

1. Добавить тип сервиса `web` или `api`.
2. Для `web` использовать текущий механизм открытия вкладки и вставки.
3. Для `api` добавить отправку `POST`-запроса.
4. Добавить настройки локального сервиса:
   - название;
   - URL;
   - метод;
   - шаблон тела запроса;
   - заголовки при необходимости.
5. Добавить предупреждения о безопасности.

### Риски

- Нельзя бездумно разрешать отправку на любые адреса.
- Нужно защититься от случайной отправки чувствительного текста.
- Пользователь должен явно включать локальные API-сервисы.

### Файлы

- `services.js`
- `custom-services.js`
- `background.js`
- `settings.js`
- `options.html`
- `options.js`
- `README.md`

### Критерии готовности

- Можно добавить локальный веб-сервис.
- Можно добавить локальный API-сервис.
- Отправка на локальный адрес работает только после явного включения.
- Пользователь видит предупреждение о безопасности.

## 19. Определение готовности всего проекта

Дорожная карта считается выполненной, когда:

- пользователь может создать собственную команду через интерфейс;
- команда появляется в контекстном меню;
- команда работает с выбранным сервисом;
- настройки можно перенести на другой компьютер;
- есть профили под разные задачи;
- ошибки вставки понятны;
- есть ZIP-релиз;
- проверки запускаются автоматически;
- документация объясняет установку, настройку, безопасность и развитие проекта.
