# Руководство разработчика

Этот документ описывает, как безопасно дорабатывать расширение **Send to AI**.

## Основной принцип

Проект должен оставаться рабочим после каждого изменения. Не нужно делать большие переписывания без промежуточных проверок.

## Ветки

Не вноси изменения напрямую в `main`.

Рекомендуемая схема:

1. Создать отдельную ветку под задачу.
2. Внести изменения.
3. Запустить проверки.
4. Открыть pull request в `main`.
5. Проверить результат вручную в браузере.
6. Только после этого сливать изменения.

Пример названия ветки:

```bash
git checkout -b feature/custom-commands
```

## Проверки

Перед коммитом запускай:

```bash
npm run check
```

Команда выполняет unit-тесты и синтаксическую проверку основных JavaScript-файлов.

Отдельно можно запустить только тесты:

```bash
npm run test
```

## Структура проекта

Основные файлы:

- `manifest.json` — описание расширения, права, иконки, popup, страница настроек.
- `background.js` — главный диспетчер действий: меню, вкладки, запуск вставки.
- `services.js` — список ИИ-сервисов и специальных команд.
- `menus.js` — построение контекстного меню.
- `settings.js` — настройки и их нормализация.
- `insertion.js` — поиск поля ввода и вставка текста на страницу сервиса.
- `context-prompts.js` — prompt'ы для страниц и ссылок.
- `youtube.js` — YouTube-ссылки и YouTube-prompt'ы.
- `popup.js` — логика быстрого окна расширения.
- `options.js` — логика страницы настроек.
- `test/` — unit-тесты.

## Как добавить новый ИИ-сервис

1. Открой `services.js`.
2. Добавь объект в `SERVICE_CONFIGS`.
3. Укажи:
   - `id` — внутренний идентификатор;
   - `title` — название в меню;
   - `urlPattern` — шаблон уже открытых вкладок;
   - `newUrl` — адрес для новой вкладки;
   - `profile.selectors` — список CSS-селекторов поля ввода.
4. Открой `manifest.json`.
5. Добавь домен сервиса в `host_permissions`.
6. Добавь или обнови тесты, если меняется логика меню.
7. Запусти `npm run check`.
8. Проверь вручную в браузере:
   - сервис открывается;
   - текст вставляется;
   - уже открытая вкладка переиспользуется.

## Как добавить встроенную специальную команду

1. Открой `services.js`.
2. Добавь объект в `SPECIAL_ACTIONS`.
3. Укажи:
   - `id`;
   - `title`;
   - `serviceId`;
   - `transformText`.
4. Убедись, что команда появляется в меню.
5. Добавь тесты для меню и настроек, если нужно.
6. Запусти `npm run check`.

Важно: новые крупные сценарии лучше добавлять через будущую систему пользовательских команд, а не зашивать в `SPECIAL_ACTIONS`.

## Как менять prompt'ы

Prompt'ы для страниц и ссылок находятся в `context-prompts.js`.

Prompt'ы для YouTube находятся в `youtube.js`.

После изменения prompt'ов обнови соответствующие тесты:

- `test/youtube.test.js`;
- `test/link-prompts.test.js`;
- другие тесты, если они завязаны на текст prompt'а.

## Как менять настройки

Если добавляется новый ключ настроек:

1. Добавь ключ в `SETTINGS_STORAGE_KEYS`.
2. Добавь значение по умолчанию в `buildDefaultSettings`.
3. Обнови `normalizeSettings`, чтобы старые настройки не ломались.
4. Обнови страницу настроек, если ключ должен быть виден пользователю.
5. Добавь тест в `test/settings.test.js`.

## Как менять меню

Контекстное меню строится в `menus.js` функцией `buildMenuDescriptors`.

После изменения меню обнови тесты в `test/menus.test.js`.

## Ручная проверка расширения

1. Открой `chrome://extensions/` или `edge://extensions/`.
2. Включи режим разработчика.
3. Нажми **Загрузить распакованное расширение**.
4. Выбери папку проекта.
5. Выдели текст на любой странице.
6. Проверь контекстное меню **Отправить в AI**.
7. Проверь отправку минимум в ChatGPT и Qwen.
8. Проверь страницу настроек.
9. Проверь popup по нажатию на иконку расширения.

## Релизная проверка

Перед релизом:

```bash
npm run check
npm run build:zip
```

После сборки проверь ZIP из папки `dist/`.

Подробности описаны в `RELEASE.md`.
